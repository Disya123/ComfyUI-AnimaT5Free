# ComfyUI-AnimaT5Free — установка

Переписанная интеграция для исходной T5-Free C0/C1-модели и слитных F128 FT
чекпоинтов. Текущие веса переобучать или конвертировать не нужно.

## Обновление

1. Закрой ComfyUI.
2. Замени целиком папку `ComfyUI/custom_nodes/ComfyUI-AnimaT5Free` папкой из
   архива. Файлы моделей в `models/` оставь на месте.
3. Установи зависимости тем Python, которым запускается ComfyUI. Для Windows
   portable, из корня portable-дистрибутива:

   ```bat
   python_embeded\python.exe -m pip install -r ComfyUI\custom_nodes\ComfyUI-AnimaT5Free\requirements.txt
   ```

   Для обычной установки, из папки ComfyUI:

   ```bat
   python -m pip install -r custom_nodes/ComfyUI-AnimaT5Free/requirements.txt
   ```

4. Перезапусти ComfyUI.

## Твой F128 workflow

- **Load Diffusion Model**: текущий слитный `anima-ft*-f128.safetensors`, в
  котором уже есть `f128_receiver.*`.
- **Load CLIP**: прежний упакованный `qwen_35_2b_base.safetensors` с Qwen,
  tokenizer, конфигом и C0/C1. Произвольный Qwen-файл с тем же именем не подходит.
- Между Load CLIP и обоими CLIP Text Encode можно поставить новый узел
  **Anima Text Encoder Mode** и выбрать **F128**. Он пропускает вычисление C0/C1.
- Положительный и отрицательный промпты подключи к этому CLIP. Дальше — твои
  обычные KSampler, VAE и остальные узлы.

Старый workflow без нового узла тоже работает: по умолчанию кодировщик выдаёт
C0/C1 conditioning вместе с заранее рассчитанным F128 carrier в metadata.
Выбор пути больше не зависит от того, какая diffusion-модель загрузилась первой.
При использовании узлов усреднения/изменения conditioning выбирай **F128**
явно: тогда они изменяют сам F128-тензор, а не только C0/C1 часть.

Для исходной T5-Free модели выбери **T5-Free C0/C1**. Для одного CLIP,
подключённого к обоим семействам моделей, оставь **Both (compatibility)**.

Старый мини-файл `anima-f128-mode` и формат с receiver внутри отдельного
TE-файла больше не используются. Receiver должен находиться в diffusion-файле.

## Что изменилось

У каждого F128-чекпоинта теперь собственный receiver. Нет глобальных
`F128_CTX`, `F128_ACTIVE`, `holder.z` и вечного флага «F128 загружен».
Загрузка второго чекпоинта не подменяет receiver первого и не переключает
текстовый путь исходной модели.

Математика d1c, padding K/V, нормализация и явный attention сохранены.
Timestep передаётся без `/1000`; для F128 сохранены raw VAE coordinates.
Пустой F128-промпт кодируется как один пробел, как в обучении.

Полный Qwen загружается перед каждым text encode, в том числе после клонирования
CLIP. Во время KSampler Qwen не исполняется. Receiver включён в структуру
diffusion-модели и следует за ней при полной выгрузке. Qwen и receiver должны
помещаться на своих устройствах исполнения целиком; dynamic/Aimdo для них не
используется.

Для F128 всё ещё нужен **T5 tokenizer только для разметки строк**. T5-модель
не загружается. Этот рефакторинг не меняет обучение и не исправляет качество
следования промптам или перенос на другие языки.

Кэши теперь разделены по весам, tokenizer и версии обработки, находятся в
`models/anima_t5free_cache/`. Старые кэши внутри custom_nodes игнорируются.
В [английском README](README.md) описаны offline-режим, перенос кэша и ограничения
prompt weighting.

Проверки и оставшиеся ограничения описаны в [TESTING.md](TESTING.md).
